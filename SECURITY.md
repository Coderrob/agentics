# Security Policy

## Supported Versions

| Version | Supported |
| ------- | --------- |
| 0.x     | ✅        |

## Reporting a Vulnerability

**Do not open a public GitHub issue for security vulnerabilities.**

If you discover a security vulnerability in this project, please report it responsibly:

1. **Email** — Send a description of the vulnerability to the repository maintainers via the contact
   information listed on the GitHub profile.
2. **GitHub Private Vulnerability Reporting** — Use GitHub's built-in
   [private vulnerability reporting](../../security/advisories/new) feature if enabled on this
   repository.

Please include:

- A description of the vulnerability and its potential impact.
- Steps to reproduce or a minimal proof-of-concept.
- Any suggested mitigations or fixes, if known.

## Response Timeline

| Stage               | Target                 |
| ------------------- | ---------------------- |
| Acknowledgement     | Within 3 business days |
| Initial assessment  | Within 7 business days |
| Patch or mitigation | Dependent on severity  |

## Disclosure Policy

We follow coordinated disclosure. We ask that you give us reasonable time to investigate and address
the issue before any public disclosure. We will credit reporters in the release notes unless they
prefer to remain anonymous.

## Scope

This policy applies to the source code, packages, and tooling in this repository. It does not cover
third-party dependencies; please report those vulnerabilities directly to the upstream maintainers.
